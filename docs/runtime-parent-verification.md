# 時間発展中の保存再配分の検証

2026-11-02。対象は、前回の実充填層計算が再メッシュ後の90262刻みで停止した親面の積分精度不足。載荷・平衡状態の空隙率40%→10%という到達目標を維持し、材料・摩擦・形状・周期境界・載荷速度・積分誤差予算を変更していない。

## 今回の変更

`runtime_quadrature.py` に次の試行配置を使う保存再配分を追加し、陽解法ソルバーの親面精度エラー処理へ接続した。設定は `surface_runtime_redistribution: conservative`、既定は `stop`。従来の接触前演算子更新手順を維持し、古い接触中チェックポイントから新実装で時間発展を開始しない。

同じ配置の誤った反力を保存しながら、その反力自体を修正する要求は一般には両立しない。今回の方式は次の順序で検査する。

1. 失敗した試行は受理せず、既存の材料点・履歴・積分則から独立した接触オブジェクトを構築する。
2. 直前に受理した配置の実際の接触ポテンシャルを再生し、保存された力・エネルギーと一致することを検査する。
3. **受理済み配置**の全周期自由度に対する接触仮想仕事、法線エネルギー、確定・力評価用の摩擦エネルギー、実接線ポテンシャル、面積と2次モーメントを保存する。
4. その制約の下で、受理済み配置・次の試行配置・既存の過去/制御姿勢の積分精度を満たす正の重みを求める。
5. 受理済み配置の実力・エネルギーを再検査し、さらに試行配置を通常の精度監査で評価する。両方に合格した候補だけをソルバーへ返す。失敗時には元の重み・履歴を変更しない。

位置・点数・摩擦履歴ベクトルを変更しない。各点の保存エネルギーは重みに応じて変更し、総量を制約する。重みの範囲は初回の時間発展中再配分における基準重みの0.5～2倍に固定し、繰返し操作による許容範囲の拡大を防ぐ。基準重みもチェックポイントへ保存する。SVD零空間、内点法、保存監査のしきい値は前回と同じ。

## 検証と再実行

[判定JSON・画像・CSV](../exports/runtime-parent-verification-001/README.md)に実行結果を保存する。停止状態の空隙率は過渡値であり、平衡圧密の結果ではない。

- 平面接触：相対精度1e-3、5e-4、2.5e-4と初期滑り0.0001、0.01 mmの6条件で、正逆各0.0001 mmの規定増分を検査する。受理済みの力・エネルギー、Coulomb境界、接触状態の保存/再開を個別に監査する。動的な圧密計算・時間刻み収束の代用ではない。
- 単体検証：既存オブジェクトの全接触状態が不変であること、再配分失敗時の状態不変、固定基準による重み上限を検査する。既存69件の回帰検証も実行する。
- 実充填層：認証済み接触前状態90206刻みから再実行し、同じ辺を90250刻みで分割する。試験の刻み上限は90275。前回の90262停止を越えられるか確認するための短区間であり、圧密完走の判定ではない。

平面接触6条件は全て合格した。12回の再配分で、受理済み反力の保存誤差は最大8.47e-16、チェックポイント再生の反力誤差は全条件で0。既存回帰69件、新規4件が合格した。新規4件は成功2条件・棄却時の状態不変・固定基準重みの範囲を検査する。

既存の動く平面接触ソルバーも再検証し、再メッシュ、保存/再開の配列一致、明示的な有効化の要件、棄却時の軌道不変、3刻み継続が全て合格した。平面の12増分で最大接線力/法線力は0.3000000000000002、摩擦散逸増分の最小値は0で、μ=0.3の境界を丸め誤差内で満たした。

## 実充填層の結果：停止は未解消

90250刻みの再メッシュは前回と同じく承認された。しかし90262刻みの次の試行で親面3166の法線積分監査が不合格となり、時間発展中の再配分を呼び出したところ、内点法が `HiGHS Status 8: Infeasible` を返した。提案は棄却し、試行を受理しなかった。最後の受理空隙率は36.94169748%で、**前回より先へ進んでいない**。

前回と共通する56受理刻みで、時間・空隙率・軸圧縮・圧力・運動/内部エネルギーが数値的に完全一致した。比較図で両曲線が重なるのはこのため。左の保存誤差図では、誤差0を対数軸の表示下限1e-18に置いている。CSVには元の0を保持する。

停止時の相対反力誤差は約2.104%、絶対力超過1.3421e-7 N。材料/境界体積、正のJ、エネルギー収支、運動エネルギー、Coulomb境界、参照体積、貫入の各検査は合格しているが、静的平衡・載荷経路・目標空隙率・除荷・周期完了は不合格である。これを平衡解として返していない。

この実行不能判定は、現実装の安全余裕、成分ごとの絶対予算配分、保持姿勢、固定点と重み上下限、受理済み配置の保存制約の組合せに対する結果である。別の積分再配分法まで不可能と証明したものではない。診断用に制約の一部を外す試験は物理計算へ採用しない。

## 制約の切り分け

今回の同じ実装で保存した90262刻みのチェックポイントを使い、失敗する1刻みだけを診断した。保存則は維持したまま、別々のLPで精度条件の組合せを調べた。緩めた診断解をソルバーへ返さず、物理軌道は進めていない。

| 精度条件 | 実行可能性 |
|---|---|
| 受理済み・過去/制御・次配置の全17応答ブロック | 不可 |
| 次配置を除く13ブロック | 不可 |
| 受理済み配置の4ブロックだけ | 不可 |
| 次配置の4ブロックだけ | 不可 |
| 精度条件なし、保存則と重み範囲のみ | 可、重み変更0 |

既存点は96個、保存行列は9748行で、有効な零空間は37次元。保存則だけで自由度が全て失われたわけではない。受理済み配置だけでも不合格となるため、まず既存の監査と、射影LPの精度条件・絶対予算配分を整合させる必要がある。監査は相対成分誤差を差し引いた超過のL1合計に全体予算を適用するが、現LPはさらに親面・各成分へ均等配分し、安全余裕として許容量を半分にする。後者は十分条件であり、前者と同値ではない。

元の重みでの受理済み配置の力超過合計は1.19823719e-7 Nで、実際の上限1.25e-7 N以内。一方、LPの成分均等配分だけでは最大9.831倍、安全余裕込みでは19.662倍の超過扱いになる。これは予算の定式化が受理済みの状態を除外していることを示す。試行配置の追加や履歴条件を外すだけでは、この条件の不整合は解消しない。

次の修正では、監査と同じ**L1誤差予算をLPへ直接組み込む**ことを優先する。受理済み点の重みが受理済み配置の条件に入ることを確認した上で、次配置・過去姿勢の条件を戻して再検証する。その後も実行不能なら、積分点の追加と履歴再生を検討する。

```bash
PYTHONPATH=. OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python -m pytest -q tests/test_runtime_quadrature.py
PYTHONPATH=. OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 python tools/verify_runtime_parent.py --output results/new-runtime-plane
```

実充填層の入力チェックポイントと初期積分則は前段の公開データから復元する。今回のZIPには設定、実行時のソース、試行ごとの判定、最後の受理状態を含める。初期パイロットは単体検証で基準重み変数の取り違えが判明したため中断し、修正後に新しい出力先で全区間を再実行した。重み上限を検査する単体試験の初期値にも誤りがあり、成功側が本当に許容範囲に入る値へ修正した。失敗・中断した実行を削除せず保存した。

新規積分点の追加・履歴再生、複数回の親面再メッシュ、要素品質の回復、空隙率10%までの載荷・保持・除荷完走、空間・時間収束は未完了。固定された既存積分点では保存条件と次配置の精度を両立できない場合があり、その場合は停止する。
