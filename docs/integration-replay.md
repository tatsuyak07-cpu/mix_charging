# 追加する接触積分点の摩擦履歴を再生するための検証

前回は幾何メッシュの分割と接触積分点を分離し、既存の積分点の重み・履歴を保持した。今回は次段階として、**新しい積分点を接触中に要求したとき、既知の非接触状態から運動履歴を再生する方法**を、周期的な平面接触の単体試験で検証した。

この試験は規定された運動を新しい表面離散化で評価するもので、体積FEMの圧縮解を計算する試験ではない。計算途中で積分重みを切り替える処理、狭い辺接触領域の適応積分、連成した圧縮ソルバーの巻き戻しは実装していない。

## 条件と判定

既存の `AreaContact` の `material` モードを使用し、接触則を変更しない。単位はmm、N、MPa。接触面積1 mm²、接触厚さ0.02 mm、面積あたり法線係数20 MPa/mm、摩擦係数0.3を前回の平面接触検証から維持した。これらは接触アルゴリズムの試験用数値条件であり、焼結鉱の実測物性ではない。

離隔0.025 mmの非接触状態から、接線移動なしで0.015 mmへ近づける。その後、接線変位を0.0001 → 0.02 → 0.012 → −0.01 → 0.005 mmと変え、固着、正方向の滑り、除荷、逆方向の滑り、再反転を評価する。接触後の法線方向と離隔は一定である。

表面の分割数1・2・4、周期平面の位相0・0.125 mm、各運動区間8・16分割の12条件を使用する。位相は分割数によらず同じ物理的な移動量とした。運動の時間刻みの比較は、規定運動を何分割して接触則へ入力するかの比較であり、圧縮FEMの慣性・準静的性の検証ではない。

各条件で以下を比較する。

1. 最初の非接触状態から継続した表面接触計算。
2. 正方向の滑り後まで保存した規定運動を、最初の非接触状態から別の接触オブジェクトで再生し、その後も継続した計算。
3. 同じ途中位置で接触履歴を持たずに初期化した負例。
4. 独立したスカラー弾性すべり・Coulombリターンマッピング。弾性すべりに変位増分を加え、摩擦上限で切り詰め、反力、弾性エネルギー、塑性すべり仕事を積分する。

平面では単位面積あたり接線ばね係数は10 MPa/mm、上限はμ×法線反力である。法線反力・ポテンシャルは同じ既存の `barrier` 関数を使うため、この試験を法線則そのものの独立検証とは扱わない。摩擦のスカラー計算は表面のアンカー・接線基準・接触キーを使わず構成した。

さらに一定法線力での往復すべりの閉形式を使い、総摩擦仕事も確認する。接線反力上限をT、弾性限界変位をa=T/10とすると、今回の経路の塑性すべり総量は0.065−5a mmであり、仕事はT(0.065−5a) N mmとなる。初回降伏にa、2回の反転に各2aを要するためである。各刻みのリターンマッピングとは別に、全サイクルの閉形式を照合する。

解析値との絶対誤差1e−10、再生と継続との差1e−12、反力釣り合い1e−10、Coulomb上限0.3を判定に使用する。履歴初期化の負例は接線反力差が1e−4 N以上となることを確認する。これらはこの単体検証の許容値であり、本体の移行監査や圧縮計算の許容値を変更していない。

## 結果

検証結果は[判定JSON](../exports/integration-replay-002/summary.json)、[継続計算・解析値の時系列CSV](../exports/integration-replay-002/trace.csv)、[履歴比較図](../exports/integration-replay-002/history-replay.png)、[全データZIP](../exports/integration-replay-002.zip)に保存する。

履歴再生の12条件すべてで判定に合格した。再生後の反力・エネルギー・摩擦増分と継続計算との差は0であった。スカラー解析値との最大絶対誤差は接線反力1.11×10⁻¹⁵ N、法線反力1.27×10⁻¹⁵ N、摩擦仕事増分3.52×10⁻¹⁸ N mmであった。全条件で反力釣り合い・Coulomb上限・非負の摩擦散逸も確認した。

表面分割数・周期位置・運動分割数を変えた条件間の最終接線反力の差は2.23×10⁻¹⁶ N、総摩擦仕事の差は1.96×10⁻¹⁸ N mmであった。総摩擦仕事は約0.00105375152140 N mmで、全サイクルの閉形式とも一致した（[閉形式との照合](../exports/integration-replay-002/closed-form-check.json)）。

一方、同じ滑り後の位置で履歴を初期化すると接線反力が0となり、保持すべき約0.0189837 Nを失った。最終位置が分かっているだけでは接触点の過去の滑りを復元できないことを、この負例で確認した。

既存の摩擦履歴・接触記録関連17テストも実行し、すべて合格した。検証用プログラムと文書のみの追加で、本体は変更していないため、全体300テストは今回再実行していない。初回の幾何証明による停止と、開発中の2回のJSON保存エラーは失敗ログとして保持した。初回エクスポートでもNumPy真偽値のJSON保存エラーがあり、部分出力と当時のスクリプトを保持し、修正後は別の新規出力先を使用した。

## 狭い接触領域の積分を別に検証

積分点の間に接触がある場合を調べるため、長さ1 mm・横幅1 mmの仮想的な帯を設け、離隔を既知の二次関数として規定した。接触領域の幅0.02・0.002・0.0002 mm、中心位置0.37・0.501・0.529 mm、最小離隔0.005・0.0005 mmの18条件を評価した。これは三角形表面や体積FEMの代わりに使う物理モデルではなく、将来の積分処理のための既知の検証関数である。

均等な中点16・32・64・128点での積分を、既知の距離下限から活性区間を検出した後の適応Gauss積分と比較した。Gauss8点・16点の差で再分割を判断し、相対許容値1e−5・1e−6を比較した。別のQUADPACK積分を基準値とし、同じ正規化形状で反力・エネルギーが帯幅に比例することも確認した。

18条件すべてで適応積分が基準値と一致した。最大相対誤差は約1.68×10⁻¹²、幅比例の誤差は約1.37×10⁻¹²だった。一方、均等中点積分では18条件すべてに少なくとも1つの分割数で完全な見逃しがあり、128点でも12条件で反力を0と評価した。[判定JSON](../exports/integration-replay-002/narrow-summary.json)、[比較図](../exports/integration-replay-002/narrow-integration.png)に記録した。

この検証では二次関数の正確な距離下限を使用できる。**任意の変形したFEM表面について同じ下限を求める処理は未実装**である。積分次数の比較だけでは、どちらの規則も見逃す接触領域を検出できない。したがって、今回の合格を実充填層の辺接触の解決や、2次元面積分の収束とは扱わない。摩擦履歴の復元試験とこの法線積分試験も、まだ連成していない。

## 圧縮計算へ進めるために残る工程

今回の方法が利用できるのは、追加点について、非接触と確認できる時点以降の**全ての必要な材料運動と接触相手の運動**が既知の場合である。現在位置だけから過去の滑りは復元できない。圧縮ソルバーの接触JSONは診断記録であり、完全な巻き戻し用チェックポイントではない。

次は今回の既知の帯での検証を2次元の三角形面へ拡張し、距離下限による接触候補の検出と、体積メッシュによらない表面積分を検証する必要がある。その上で、細分化した積分規則を非接触チェックポイントで導入し、体積材料状態・速度・境界自由度も含めて連成計算を巻き戻して再実行する方式を検証する。積分規則を接触中に突然置き換えると力・エネルギーが変わり得るため、履歴再生が成功するだけでは途中切り替えを採用できない。

曲面での法線回転、非一様すべり、接触パッチの出入り、一般の再メッシュは今回の対象外である。0.1 MPaの平衡到達、空隙率40%→10%の圧密、100 mm充填層の代表性、メッシュ収束はいずれも未確認のままである。今回、既存の圧縮計算の停止ガードを解除していない。

## 再現と保存

```bash
PYTHONPATH=. OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 \
/workspace/environment/mix_charging/.venv/bin/python \
  -m tools.verify_integration_replay --output results/new-integration-replay
```

狭い帯の検証は同じ環境で次のコマンドを使用する。

```bash
PYTHONPATH=. OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 \
/workspace/environment/mix_charging/.venv/bin/python \
  -m tools.verify_narrow_integration --output results/new-narrow-integration
```

出力先は必ず新規ディレクトリを指定する。依存関係や環境設定は変更していない。全条件の規定運動、参照節点・要素、積分面積、途中と最終の確定履歴および力評価状態を保存する。初回の運動区間の分割不足による幾何証明の停止と、開発中のJSON保存エラーも、元のログ・試行スクリプトを残す。
